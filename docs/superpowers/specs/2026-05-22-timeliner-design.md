# Timeliner Design Spec
_2026-05-22_

## Overview

A generic, fork-able timeline static site built with Astro + TypeScript + pnpm. Records any time-based content (travel, life events, reading logs, project history) as Markdown files. Forkers configure the entire experience via a single `timeliner.config.ts` at the project root.

Derived from the us-trip project but with all travel-specific logic removed and replaced with a theme system and generic content schema.

---

## Tech Stack

- **Framework**: Astro 6
- **Language**: TypeScript
- **Package manager**: pnpm
- **Test runner**: Vitest
- **Deployment**: GitHub Pages (same as us-trip)
- **No new dependencies** beyond what us-trip already uses

## Configuration

`timeliner.config.ts` is the single entry point for all customization:

```ts
export default {
  title: "My Timeline",
  description: "A personal record",
  theme: "chalk",                          // built-in name or path e.g. "./src/styles/themes/my-theme.css"
  lang: {
    primary: "zh",
    secondary: "en",                       // false to disable second language
  },
  photos: {
    thumbWidth: 400,
  },
}
```

## Content Schema

```ts
// src/content/config.ts
const days = defineCollection({
  schema: z.object({
    title: z.string(),
    date: z.coerce.date(),
    photos: z.array(z.string()).optional(),
  })
})
```

Example entry at `src/content/days/2026-04-05.md`:

```markdown
---
title: 抵达京都
date: 2026-04-05
photos:
  - 2026-04-05/arrival.jpg
  - 2026-04-05/hotel.jpg
---

正文内容，支持完整 Markdown。
```

## Data Flow

```
src/content/days/*.md
  → Astro Content Collections (Zod validation)
  → utils/content.ts (getCollection, sort by date descending)
  → pages/index.astro
  → Timeline.astro
  → Entry.astro × N
       → PhotoGrid.astro (only when entry.photos exists)
```

## Theme System

### Built-in themes

Four themes ship with the template:

| Name       | Background  | Accent         | Font         | Character          |
|------------|-------------|----------------|--------------|--------------------|
| chalk      | #1c1c1c     | white          | system sans  | Dark minimal       |
| ocean      | #0a1628     | #38bdf8 blue   | system sans  | Dark, calm         |
| neon       | #0d0d0d     | pink/cyan/yellow glow | monospace | Cyberpunk       |
| parchment  | #f5f0e8     | #8b6f47 brown  | Georgia serif | Warm journal      |

Each theme is a CSS file that only defines variables:

```css
/* styles/themes/chalk.css */
:root {
  --bg: #1c1c1c;
  --text-primary: #ffffff;
  --text-secondary: #888888;
  --text-muted: #444444;
  --node-active: #ffffff;
  --node-inactive: #555555;
  --line: #333333;
  --font-body: -apple-system, sans-serif;
  --font-heading: -apple-system, sans-serif;
}
```

`global.css` contains all layout/structural styles using only these variables. Switching theme = one string change in config.

### Custom themes

`theme` in config accepts a path to any CSS file:

```ts
theme: "./src/styles/themes/my-theme.css"
```

`BaseLayout.astro` detects whether the value starts with `.` and routes accordingly. Built-in themes double as documentation — copy one, change the variables.

## Bilingual Support

- `pages/index.astro` renders in `lang.primary` language
- `pages/en/index.astro` renders the same content with English UI strings (date format, header labels)
- When `lang.secondary` is `false`, `en/index.astro` returns an empty `getStaticPaths` array and no pages are generated — no files need to be deleted

---

## Photo Support

Photos are optional per entry. `PhotoGrid.astro` only mounts when `entry.data.photos` is defined and non-empty. Missing image files are silently skipped at render time — the build does not fail.

Photo paths in frontmatter are relative to `public/photos/`. Thumbnails are generated by `scripts/gen-thumbs.sh` into `public/photos-thumb/`.

---

## Edge Cases

| Scenario | Behavior |
|---|---|
| Missing `title` in frontmatter | Zod error at build time, points to file |
| Unparseable `date` | Zod `coerce.date()` fails at build time |
| `photos` file not found | Silently skipped, build succeeds |
| `lang.secondary: false` | `en/` pages not generated, no manual deletion needed |
| Custom theme path wrong | Browser 404 on CSS, build succeeds; README warns to verify path |
